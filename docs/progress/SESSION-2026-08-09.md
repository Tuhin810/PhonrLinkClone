## The open bug: remote touch does nothing

**Symptom:** the Mac sends `input_tap`, the Mac logs `[input-test] tapping 0.5, 0.5`, and
nothing happens on the phone.

**What has been ruled out:**
- The accessibility service **is** enabled — `enabled_accessibility_services` lists
  `com.phonelinkclone/com.phonelinkclone.RemoteInputService`, and the app stopped showing the
  "Enable remote control" prompt, meaning `RemoteInputService.isRunning()` returns true.
- The link is up (`[link] connected`) and screen frames flow over the same socket, so transport
  and encryption are fine.
- `ScreenCaptureModule.tap` logs on entry and **never logged** — so JS is not reaching the
  native module. The break is in the phone's JS routing or envelope handling, not in Kotlin.

**Instrumentation already added and installed** (this is where to pick up):
- `ScreenCaptureModule.logDebug(message)` writes to logcat under tag `PhoneLinkJS`. RN's
  `console.log` only reaches Metro, so this is the only way to trace anything while the app is
  backgrounded.
- Trace points: `envelope <type>` on every inbound envelope, `routing input_*` in the router,
  and `handleInput <type> screen=WxH` in the handler.

**The next command to run** — it will show exactly which of the three trace points fires:
```bash
cd android-app && npx react-native start          # Metro, in its own terminal
adb shell am force-stop com.phonelinkclone
adb shell am start -n com.phonelinkclone/.MainActivity
cd mac-app && env -u ELECTRON_RUN_AS_NODE npx electron . --input-test 0.5 0.5
adb logcat -d -t 300 | grep -E "PhoneLinkJS|ScreenCapture|PhoneLinkInput"
```
Read it as:
- **no `envelope` lines** → the phone is dropping frames before the router; suspect a stale
  Metro bundle with an older `@phonelink/shared` that fails validation on `input_tap`.
  Restart Metro with `--reset-cache`.
- **`envelope` but no `routing`** → the `type.startsWith('input_')` branch is unreachable;
  check the branch order in `useNotificationMirror`'s `onEnvelope`.
- **`routing` but no `handleInput`** → `mirrorRef.current` is stale.
- **`handleInput … screen=0x0`** → the screen-size lookup failed; the self-heal fetch is already
  in place, so check `getScreenSize`.

**Prime suspect:** a stale Metro bundle. The APK was rebuilt many times, but the JS comes from
the dev server, and `@phonelink/shared` lives outside the project root. If the phone were
running protocol v3 while the Mac ran v4, pairing would have failed — it did not — so this is
not certain, but `--reset-cache` is the cheapest first move.
